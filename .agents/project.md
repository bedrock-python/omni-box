# Project profile

## About

- What this repository is: `omni-box`, a Python library for the Transactional Outbox and Transactional Inbox patterns in async services, published on PyPI.
- Who uses it: async Python services that store events in the same database transaction as their state and publish them later (outbox), or that store broker messages with deduplication before handling them (inbox). The adapters cover PostgreSQL and Kafka.
- Language, version and main frameworks: Python 3.12 and newer (PEP 695 generics), asyncio only. Runtime dependencies are `pydantic` 2, `orjson` and `structlog`. Optional extras: `postgres` (SQLAlchemy 2 + asyncpg), `kafka` (aiokafka) and `metrics` (prometheus-client), in `omni_box/infra/`; `opentelemetry` (`OpenTelemetryStep`); `settings` (pydantic-settings) and `dishka`, in `omni_box/contrib/`.
- Where the documentation lives: https://bedrock-python.github.io/omni-box/, built with Zensical from `docs/` (`zensical.toml`). `docs/agents.md` is the one-page reference for coding assistants.

## Commands

| Task | Command |
|---|---|
| Install dependencies | `make install` (`uv sync --all-extras --group dev`), the same set CI installs. CONTRIBUTING.md gives `uv sync --group dev`, which leaves the extras out. The unit tests still collect that way, because the `test` group lists every extra's package except `opentelemetry-sdk`. |
| Format | `make fmt`: `uv run ruff format .`, then `uv run ruff check --fix .` |
| Lint and type-check | `make check`: `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy omni_box`. CI runs the same three. |
| Test | `make test-unit` (`uv run pytest -m unit`). `make test` adds coverage with `--cov-fail-under=90` and still runs only the unit tests, although CONTRIBUTING.md calls it the full suite. `make test-integration` (`uv run pytest -m integration`) needs Docker. CI runs `uv run pytest -m unit --cov=omni_box --cov-report=xml --cov-fail-under=90` on Python 3.12 and 3.13, and `uv run pytest -m integration` in a separate job. |
| Run locally | A library: nothing to run. The docs: `make docs-serve`. |
| Stop the local run | Ctrl+C in the terminal of `make docs-serve`. |

## Conventions

- Default branch: `master`. A ruleset requires a pull request and the `All checks passed` check to change it, and the pre-commit hook `no-commit-to-branch` refuses local commits to it.
- Issue tracker: GitHub Issues of this repository; refer to an issue as `#123`.
- Branch names: `<type>/<short-description>`, such as `feat/my-feature` (CONTRIBUTING.md).
- Commit messages: Conventional Commits with an optional scope, such as `fix(postgres): ...`. The `conventional-pre-commit` hook enforces them (`uv run pre-commit install --hook-type pre-commit --hook-type commit-msg` installs every hook; CONTRIBUTING.md installs only the commit-message one, so ruff does not run at commit time). Pull requests are squash-merged. The squash title is the pull request's title, or the commit's own title when the pull request has one commit, and release-please reads it, so both are Conventional Commits.
- Language of pull request titles and descriptions: English.
- Where specs and design notes go: in the pull request description; the repository has no place for them. `docs/architecture.md` describes the design for users.

## Boundaries

- `CHANGELOG.md` is generated by release-please: never edit it by hand, and never add an `## [Unreleased]` section, even though the pull request template's checklist asks for one. `docs/changelog.md` is a copy made when the docs build, and git ignores it.
- The version lives in `omni_box/__version__.py`, on the line marked `# x-release-please-version`, and in `.release-please-manifest.json`; release-please bumps both. Never change them by hand.
- `docs/agents.md` is part of the public API: it changes in the same pull request as the API (CONTRIBUTING.md, "The agents page").
- Files from the engineering-assets hub (`AGENTS.md` explains how it works) include the copy-page files (`docs/assets/javascripts/copy-page.js`, `docs/assets/stylesheets/copy-page.css`, `overrides/main.html`, `scripts/emit_markdown.py`), `.github/workflows/docs.yml`, `.github/workflows/release-please.yml`, `.github/dependabot.yml`, `.editorconfig` and `CODE_OF_CONDUCT.md`. Change them in the hub; a change here makes the file this repository's own.
- Never publish to PyPI or create a release by hand: release-please creates the release, and `publish.yml` publishes it. Its manual `workflow_dispatch` is for maintainers.

## Notes

- Architecture (`docs/architecture.md`): three layers, with dependencies pointing `infra` → `application` → `core`. `omni_box/core` knows nothing about SQLAlchemy or Kafka. The library has no Unit of Work: the calling service owns every transaction.
- Releases: release-please opens its pull request with the workflow's own token, so CI does not start on it. Close and reopen the release pull request to run CI, then merge it. `publish.yml` publishes to PyPI when the Release Please run on `master` completes and a tag `omni-box-v<version>` points at its commit. Only `feat`, `fix`, `perf` and `revert` reach the changelog. Before 1.0, a breaking change bumps the minor version.
- Tests: every test carries the marker `unit` or `integration` (`--strict-markers`); `asyncio_mode = "auto"`. `tests/integration/` starts PostgreSQL 17 and Kafka in Docker through testcontainers, and its tests are skipped without Docker. One test in `tests/integration/postgres/test_resilience.py` is also marked `unit`, so `-m unit` collects it. The autouse fixture in `tests/integration/conftest.py` then starts a PostgreSQL container, or skips the test when Docker is not available.
- Code style (CONTRIBUTING.md): type hints on every function, tests included; Google-style docstrings on the public API only; lines up to 120 characters; double quotes; comments only for a non-obvious why.
